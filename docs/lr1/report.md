## Цель и результат

Цель — реализовать обмен между клиентом и сервером через сокеты,
сравнить UDP и TCP, вручную сформировать HTTP-ответ и обработать запрос.
Сокет — объект, через который программа отправляет и получает данные по сети.
На одном компьютере клиент и сервер обращаются к адресу `127.0.0.1`,
а порт определяет, какому приложению предназначены данные.

Выполнены пять заданий. Для чата используется TCP и `threading`:
несколько экземпляров одного клиента работают с общим сервером.
HTTP-журнал принимает оценки и объединяет их по предмету в словаре памяти.
Это объём выполнения для уровня 100% согласно
[заданию курса](https://rendex85.github.io/ITMO_ICT_WebDevelopment_Docs/lab1/assignment/).
Окончательную оценку выставляет преподаватель после проверки и защиты.

| Задание | Реализация |
|---|---|
| 1. UDP | Обмен приветствиями между двумя процессами |

## Средства реализации

Основной модуль — `socket` из стандартной библиотеки Python.
`threading` нужен для параллельного обслуживания пользователей чата.
`json` сериализует запросы вычислений, `pathlib` работает с путями,
`urllib.parse` разбирает данные HTML-формы, `html.escape` защищает вывод текста
предмета от интерпретации как HTML. Веб-фреймворки и `http.server` не используются
в серверах заданий.

Команды запуска программ выполняются из папки автора. Из корня репозитория:

Общий код в `common` задаёт границы TCP-сообщений и вручную разбирает HTTP.
Запускаемые модули содержат `if __name__ == "__main__"`:
импорт модуля не запускает сервер автоматически.

## Задание 1. Обмен сообщениями по UDP

### Реализация

`task1/server.py` создаёт сокет `socket.AF_INET`, `socket.SOCK_DGRAM`.
Первый параметр выбирает IPv4, второй — UDP. Сервер вызывает `bind`,
чтобы принимать сообщения на адресе `127.0.0.1:9001`.

```python
data, address = server.recvfrom(4096)
print(f"{address}: {data.decode('utf-8', errors='replace')}")
server.sendto(b"Hello, client", address)
```

`recvfrom` возвращает содержимое датаграммы и адрес отправителя.
По этому адресу сервер отправляет ответ. На сервере выводится
`Hello, server`, на клиенте — `Hello, client`.

Клиент в `task1/client.py` отправляет приветствие через `sendto`,
затем ждёт ответ через `recvfrom`. Данные по сети передаются в байтах:
при получении клиент декодирует их в строку UTF-8.

### Запуск и результат

В первом терминале:

```sh
python3 -m laboratory_work_1.task1.server
```

Во втором:

```sh
python3 -m laboratory_work_1.task1.client
```

Клиент печатает `Hello, client`. Сервер печатает адрес клиента и
`Hello, server`. Номер клиентского порта назначает операционная система,
поэтому он может отличаться при каждом запуске.

Сервер продолжает принимать сообщения до Ctrl+C. Если сервер недоступен,
клиент прекращает ожидание через пять секунд и сообщает об ошибке.

### Особенность UDP

UDP сохраняет границы датаграмм, но не гарантирует их доставку и порядок.
Здесь нет повторных отправок: задача проверяет простой обмен.
Для этой пары коротких сообщений буфер 4096 байт достаточен.

## Задание 2. Площадь трапеции по TCP

### Вариант

Номер в журнале — 11. Варианты повторяются с периодом 4:

```text
(11 - 1) % 4 + 1 = 3
```

Вариант 3 — площадь трапеции. Клиент вводит два основания `a`, `b`
и высоту `h`. Сервер вычисляет `S = (a + b) * h / 2`.

### Реализация

`task2/client.py` преобразует введённые строки в числа, устанавливает
TCP-соединение и отправляет три значения в виде JSON-списка:

```json
[4, 6, 3]
```

`task2/server.py` слушает порт 9002. Он читает запрос и вычисляет площадь:

```python
a, b, h = request
if min(a, b, h) <= 0:
    raise ValueError("Основания и высота должны быть положительными")
response = {"area": (a + b) * h / 2}
```

Для примера ответ будет `{"area": 15.0}`. Клиент печатает полученный результат;
сама формула находится только на сервере.
Если длина неположительная, сервер возвращает `{"error": "..."}`.

После ответа соединение закрывается. Клиенты обслуживаются последовательно.

### Границы сообщений

TCP передаёт поток байтов: один `sendall` не обязан соответствовать одному
`recv`. Поэтому `common/messages.py` добавляет к JSON перевод строки,
а принимающая сторона читает целую строку через `readline`.

### Демонстрация

В первом терминале:

```sh
python3 -m laboratory_work_1.task2.server
```

Во втором:

```sh
python3 -m laboratory_work_1.task2.client
```

Введите `4`, `6`, `3`. Клиент выведет `Площадь трапеции: 15`.

## Задание 3. Выдача HTML-страницы через HTTP

### Реализация

`task3/server.py` принимает TCP-подключения на порту 9003.
Браузер выполняет GET-запрос к `/` или `/index.html`; сервер читает
`task3/index.html` с диска и отправляет ответ через `socket.sendall`.
Путь к файлу вычисляется относительно `__file__`, поэтому не зависит от
текущего каталога при чтении файла.

Ответ формируется в `common/http.py`:

```python
lines = [
    f"HTTP/1.1 {status} {HTTPStatus(status).phrase}",
    f"Content-Type: {content_type}",
    f"Content-Length: {len(body)}",
    "Connection: close",
]
```

После заголовков стоят `\r\n\r\n`, затем — байты страницы.
`Content-Length` равен количеству байтов, а не символов: для кириллицы
в UTF-8 эти значения различаются. `Content-Type: text/html; charset=utf-8`
сообщает браузеру формат и кодировку.

Сервер читает запрос до конца заголовков и, если есть тело, до указанного
`Content-Length`. Ошибочный путь получает 404, неподдерживаемый метод — 405.
Соединение закрывается после одного ответа.

### Запуск и результат

```sh
python3 -m laboratory_work_1.task3.server
```

Откройте `http://127.0.0.1:9003/`. На странице отображается заголовок `Hello lab1`.
Файл `index.html` содержит только:

```html
<html><h1>Hello lab1</h1></html>
```
Для просмотра самого ответа:

```sh
curl -i http://127.0.0.1:9003/
```

Ожидается статус `HTTP/1.1 200 OK` и HTML после пустой строки.

## Задание 4. Многопользовательский TCP-чат

### Реализация

Один сервер `task4/server.py` обслуживает несколько экземпляров
одного клиента `task4/client.py`. Каждый участник вводит своё имя.

После `accept` сервер запускает отдельный поток для клиента:

```python
threading.Thread(target=handle, args=(connection,), daemon=True).start()
```

Словарь `clients` связывает сокет с именем участника.
Первая строка от клиента — имя, следующие строки — текст сообщений.
Сервер добавляет имя отправителя и рассылает текст остальным:

```text
Алиса: Привет всем
```

Перевод строки задаёт границу сообщения в TCP-потоке.
`makefile` и `readline` читают строку целиком, даже если она пришла частями.
JSON и отдельные типы сообщений здесь не нужны.

### Потоки и блокировка

Клиент принимает сообщения в отдельном потоке, пока основной ждёт `input`.
На сервере одна `threading.Lock` защищает словарь и отправку сообщений:
две рассылки не могут одновременно записывать одному получателю.

Это простое решение для нескольких локальных клиентов.
Медленный получатель может задержать всю рассылку. Истории сообщений
и проверки уникальности имён нет; для демонстрации используйте разные имена.

### Выход

`/quit` или закрытие соединения завершает обработчик клиента.
Сервер удаляет его из словаря и сообщает остальным о выходе.

После остановки сервера клиент, ожидающий `input`, завершится после Enter.

### Демонстрация

Сервер в первом терминале:

```sh
python3 -m laboratory_work_1.task4.server
```

В трёх других терминалах, по одной команде в каждом:

```sh
python3 -m laboratory_work_1.task4.client --name Алиса
python3 -m laboratory_work_1.task4.client --name Боб
python3 -m laboratory_work_1.task4.client --name Кэрол
```

Сообщение Алисы получают Боб и Кэрол. Сетевая копия отправителю не возвращается.
После `/quit` у Боба Алиса и Кэрол могут продолжать общаться.

## Задание 5. HTTP-журнал оценок

### Реализация

`task5/server.py` слушает порт 9005 и использует ручной разбор HTTP
из `common/http.py`.

| Запрос | Результат |
|---|---|
| `GET /` или `GET /grades` | Таблица оценок и HTML-форма, 200 |
| `POST /grades` | Добавление оценки и перенаправление 303 на `/` |
| Другой путь | 404 |
| Неподдерживаемый метод | 405 |

Форма отправляет поля `subject` и `grade`.
Сервер дочитывает тело по `Content-Length`, затем разбирает его
через `urllib.parse.parse_qs`. Предмет должен быть непустым,
оценка — целым числом от 1 до 5. Ошибка ввода получает ответ 400.

### Структура журнала

Данные находятся в обычном словаре:

```python
grades = {"Математика": [5, 4], "Web-программирование": [5]}
```

Добавление оценки занимает одну строку:

```python
grades.setdefault(subject, []).append(grade)
```

Повторное добавление по тому же предмету дополняет список,
поэтому в таблице остаётся одна строка на предмет.
Данные хранятся только в памяти и исчезают после остановки сервера.

В шаблон `task5/index.html` подставляются строки таблицы.
`html.escape` выводит название предмета как текст, даже если в нём есть HTML.
После POST сервер возвращает 303: браузер делает GET,
поэтому обновление страницы не добавляет оценку повторно.

### Демонстрация

```sh
python3 -m laboratory_work_1.task5.server
```

Откройте `http://127.0.0.1:9005/`. Добавьте оценки 5 и 4 по Математике:
появится одна строка с `5, 4`. Добавьте другой предмет.

Тот же обмен через командную строку:

```sh
curl -i --data-urlencode 'subject=Математика' --data 'grade=5' http://127.0.0.1:9005/grades
curl http://127.0.0.1:9005/
```

Сервер обслуживает запросы последовательно и закрывает соединение
после ответа. Это локальная демонстрация обычных GET/POST,
без файлового хранилища и поддержки всех возможностей HTTP.

## Вывод

UDP передаёт отдельные сообщения без установки соединения. Для TCP стороны
сначала устанавливают соединение, затем обмениваются потоком байтов. Поэтому
для TCP определены границы сообщений: запись заканчивается переводом строки.
HTTP работает поверх TCP и добавляет собственный формат запросов и ответов.
Потоки в чате нужны, чтобы один клиент, ожидающий ввода, не блокировал остальных.
